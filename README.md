# قطرة — Frontend Prototype

واجهة عربية لنظام إدارة التبرع بالدم، مبنية باستخدام HTML وCSS وJavaScript فقط.

## تشغيل المشروع

افتح `index.html` في المتصفح. لا يحتاج المشروع إلى تثبيت أو خادم.

للمعاينة المحلية مع تحديث المتصفح تلقائيًا عند تعديل HTML أو CSS أو JavaScript:

```powershell
node scripts/live-server.cjs
```

افتح `http://localhost:5501/`. لا يحتاج الخادم أي حزم إضافية. لإيقافه اضغط `Ctrl+C`.

## تقسيم الملفات

### صفحات HTML

- `index.html`: الصفحة الرئيسية العامة.
- `login.html`: صفحة تسجيل الدخول.
- `register.html`: صفحة إنشاء الحساب بمساري المتبرع والمؤسسات.
- `donor/`: جميع واجهات المتبرع، ولكل واجهة ملف ورابط مستقل.
- `hospital/`: جميع واجهات المؤسسة التي تطلب الدم فقط.
- `hospital-bloodbank/`: جميع واجهات المستشفى الذي لديه بنك دم.
- `bloodbank/`: جميع واجهات بنك الدم المركزي.
- `supervisor/`: جميع واجهات مشرف الصحة.

داخل كل مجلد توجد `dashboard.html` وبقية صفحات الدور مثل `requests.html` و`notifications.html` بحسب صلاحياته. تشترك هذه الصفحات في هيكل لوحة التحكم الموجود في `dashboard-shell.js`، لكن كل واجهة تُفتح من URL مستقل.

### ملفات JavaScript

- `landing.js`: القائمة والتنقل في الصفحة الرئيسية.
- `accounts.js`: حفظ الحسابات التي ينشئها المستخدم محليًا وإدارة جلسة الدخول.
- `login.js`: تسجيل الدخول بالحساب المنشأ باستخدام البريد الإلكتروني أو رقم الجوال وكلمة المرور.
- `register.js`: جميع خطوات التسجيل والتحقق والوثائق.
- `app.js`: لوحات التحكم والطلبات والمخزون والتقارير.

### التصميم

- `styles.css`: التصميم المشترك لكل الصفحات ودعم RTL والجوال.

## الصفحة الرئيسية العامة (index.html)

الصفحة الرئيسية العامة تعرض الآن بيانات حقيقية بدلاً من أرقام ثابتة: عدد المتبرعين المسجّلين، عدد المؤسسات المعتمدة، عدد نداءات التبرع النشطة، عدد حالات التبرع المكتملة، ومتوسط زمن استجابة الطلبات. تُقرأ هذه البيانات مباشرة من نفس مصدر بيانات لوحة التحكم (`accounts.js` وبيانات `localStorage`)، فأي حساب أو نداء أو تبرع يُضاف من أي مكان في النظام ينعكس فورًا على الصفحة الرئيسية عند تحميلها. عندما لا توجد بيانات بعد، تبقى الصفحة تعرض حالتها الفارغة الافتراضية (أصفار ورسائل "ستظهر البيانات هنا").

## مسارات إنشاء الحساب

### المتبرع

اختيار المسار ← بيانات المتبرع وفصيلة الدم ← رمز التحقق.

### المؤسسة

اختيار المسار ← بيانات المؤسسة والممثل الرسمي ← الخدمات والوثائق ← تأكيد البريد وإرسال الطلب للمراجعة.

أنواع المؤسسات المتاحة: مستشفى مركزي، مستشفى ميداني، مركز صحي، جمعية بنك دم، ومركز دم مستقل.

## نداءات التبرع

- يستطيع المستشفى الذي لديه بنك دم وبنك الدم المركزي إنشاء نداء تبرع.
- يبدأ سجل النداءات فارغًا، ولا يظهر أي نداء إلا بعد أن تنشئه المؤسسة.
- يظهر النداء للمتبرعين الذين تستطيع فصيلة دمهم التبرع للفصيلة المطلوبة، سواء كانت الفصيلة نفسها أو فصيلة متوافقة.
- تحدد المؤسسة موعد ومكان التبرع عند إنشاء النداء، ويصل الموعد للمتبرع عند قبول النداء.
- يستطيع المتبرع تأكيد الموعد مرة واحدة، وتظهر بياناته للمؤسسة صاحبة النداء.
- بعد حضور المتبرع، يؤكد الممثل الرسمي للمؤسسة عملية «تم التبرع»، فتُضاف وحدة من فصيلة المتبرع الفعلية إلى مخزون المؤسسة.
- يُغلق النداء بعد تأكيد اكتمال عدد التبرعات المطلوبة، وليس بمجرد قبول المواعيد.

## نقل وحدات الدم بين المؤسسات

طلب الدم يمر بالمراحل التالية:

1. ترسل المؤسسة طلب الدم إلى مستشفى لديه بنك دم أو إلى بنك الدم المركزي.
2. تقبل الجهة المورّدة الطلب، ثم تضغط «بدء التجهيز وحجز الوحدات». تُستبعد الوحدات المحجوزة من المخزون المتاح، ولا يمكن حجزها لطلب آخر.
3. تؤكد الجهة «الوحدات جاهزة للتسليم»، ثم «تم إرسال الوحدات». لا تُخصم الوحدات مرة ثانية عند الإرسال.
4. يؤكد الممثل الرسمي للمؤسسة الطالبة «تم استلام الوحدات».
5. إذا كانت المؤسسة الطالبة مخولة بخدمة بنك الدم، تُضاف الوحدات المستلمة إلى مخزونها مع تواريخها المحفوظة. أما المؤسسة التي لا تملك الخدمة فيُسجل الاستلام دون إنشاء مخزون لها.

تُحفظ تواريخ وتغييرات الحالة في `statusHistory` لعرض تسلسل الطلب في شاشة الإشراف. الوحدات الجديدة تحتفظ بتاريخ الجمع والانتهاء، ولا تُحجز أو تُرسل وحدة منتهية الصلاحية.

## السبرنت السابع — الإشراف والتقارير (Frontend فقط)

تستخدم الواجهات البيانات المحفوظة في المتصفح، ولا تحتاج Backend أو قاعدة بيانات خارجية. صفحات المشرف الجديدة:

- `supervisor/dashboard.html`: ملخص المؤسسات وحالات الاعتماد والخدمات والمتبرعين والطلبات والمخزون والتبرعات والنداءات والحملات، وتنبيهات النقص وأحدث العمليات وروابط التفاصيل.
- `supervisor/organizations.html`: جميع المؤسسات، بما فيها قيد المراجعة والمرفوضة، مع فصل الخدمات المطلوبة عن الخدمات المعتمدة، والبحث والفلاتر والتفاصيل والانتقال إلى مسار الاعتماد الحالي.
- `supervisor/bloodbanks.html` و`supervisor/inventory.html`: البنوك المعتمدة فقط وملخص المخزون حسب الفصيلة وحالة الوحدات والنقص والانتهاء خلال سبعة أيام.
- `supervisor/requests.html`: فلاتر الحالة والفصيلة والاستعجال والمؤسسة والبنك والمحافظة والفترة، والتفاصيل وتسلسل الحالات.
- `supervisor/donors.html` و`supervisor/donations.html`: توزيع الفصائل والمناطق والتوفر والتبرعات المؤكدة. تعرض المتابعة معرّفات المتبرعين دون بيانات الاتصال أو الهوية.
- `supervisor/appeals.html` و`supervisor/campaigns.html`: متابعة النداءات والحملات، مع فصل الدعوات والمهتمين والمشاركين عن التبرعات الفعلية.
- `supervisor/reports.html`: سبعة تقارير للمؤسسات والطلبات والمخزون والمتبرعين والتبرعات والنداءات والحملات، مع الفترة والفلاتر والرسوم والجداول المجمعة وتصدير CSV فعلي للنتائج المصفاة.

تدعم القوائم ترقيم الصفحات (10 سجلات)، والترتيب، وإعادة ضبط الفلاتر، والتحديث، وحالات عدم وجود بيانات وخطأ القراءة الجزئي. لا يضيف تحديث المشروع طلبات أو حملات أو تبرعات وهمية، ولا يمسح البيانات السابقة.

المشرف يراجع الاعتماد ضمن المسار الموجود، وتبقى صفحات المتابعة للعرض. لا تسمح بتعديل مخزون البنك أو بيانات المتبرع أو استجابته أو تجاوز مراحل طلب الدم. تعتمد صلاحيات المؤسسات على الخدمات المعتمدة للممثل الرسمي، وتسري حالته على موظفي المؤسسة أيضًا.

### مصدر البيانات والتوافق

- `supervisor-data.js`: تحويل البيانات المحلية إلى مؤشرات موحدة وتقارير؛ لا يحتسب قبول الموعد أو المشاركة في حملة تبرعًا.
- `supervisor.js`: صفحات المشرف والفلاتر والتفاصيل والرسوم والتصدير.
- `qatraBloodUnits`: سجلات الوحدات، وتتضمن `id`, `institutionId`, `organization`, `bloodType`, `status`, `collectedAt`, `expiresAt` عندما تتوفر. يدعم الملخص حالات `AVAILABLE`, `RESERVED`, `DELIVERED`, `EXPIRED`, `DISCARDED`.
- المخزون السابق في `qatraInventory` يبقى متاحًا. عند أول إضافة أو حجز في بنك، تُحوّل إجمالياته إلى سجلات وحدات محلية دون اختلاق تواريخ جمع أو انتهاء. يظهر الانتهاء «غير مسجل» عندما لا تكفي بيانات التاريخ، وتُستبعد الوحدات غير المؤرخة من تقارير فترة الجمع.
- `qatraInventorySettings.lowStockThreshold`: حد تنبيه النقص لكل فصيلة في البنك. الافتراضي `1` للحفاظ على سلوك التنبيه عند النفاد الموجود في الواجهة السابقة.
- `qatraCampaigns`: سجلات حملات محلية إن توفرت، مثل `{ id, name, org, governorate, status, date, location, bloodTypes, participants }`. صفحة المتابعة لا تنشئ الحملات؛ تكون فارغة عندما لا توجد سجلات محفوظة.
- `qatraDonations`: سجل تبرعات محلي اختياري، مثل `{ id, donorId, institution, bloodType, completedAt, callId, campaignId, bloodUnitId }`. يُدمج مع التبرعات المؤكدة في النداءات والطلبات الطوعية وتبرعات الحملات دون تكرار العملية نفسها.
- التقارير الزمنية تستخدم تاريخ إنشاء المؤسسة أو المتبرع أو الطلب أو النداء، وتاريخ وقوع التبرع، وموعد الحملة، وتاريخ جمع وحدة الدم بحسب نوع التقرير.

حماية الأدوار في هذه النسخة تنظم تجربة الواجهة فقط؛ الحسابات وكلمات المرور والبيانات محفوظة محليًا كما في النموذج السابق. هذه النسخة لا تنفذ متطلبات أمان الخادم أو قاعدة البيانات أو النشر الإنتاجي الواردة في مستند السبرنت.

### التحقق

تشغيل اختبارات دقة المؤشرات والفلاتر والخصوصية:

```powershell
node --test tests/supervisor-data.test.cjs
```

تشغيل فحص الصفحات ودورة الطلب والخصوصية والتصدير والعرض على الهاتف في متصفح مستقل ببيانات اختبار مؤقتة:

```powershell
node tests/browser-smoke.cjs
```

الفحص يستخدم Microsoft Edge على Windows افتراضيًا؛ يمكن تحديد مسار متصفح Chromium آخر عبر `QATRA_TEST_BROWSER`. لا يحتاج تثبيت حزم npm ولا يستخدم بيانات المتصفح الشخصية.

## حسابات النظام الأساسية

- البريد الإلكتروني: `supervisor@qatra.ps`
- رقم الجوال: `0599000002`

يمكن تسجيل الدخول إلى الحساب بالبريد الإلكتروني أو رقم الجوال.

## الحسابات والبيانات التجريبية

يُنشئ المشروع تلقائيًا 10 حسابات معتمدة من كل نوع، ويمكن اختيار أي منها من قائمة «دخول سريع للتجربة» في صفحة تسجيل الدخول.

| النوع | البريد الإلكتروني من 01 إلى 10 | كلمة المرور |
| --- | --- | --- |
| متبرع | `donor01@qatra.test` … `donor10@qatra.test` | `Donor@123` |
| مستشفى يطلب الدم | `hospital01@qatra.test` … `hospital10@qatra.test` | `Hospital@123` |
| مستشفى لديه بنك دم | `hospitalbank01@qatra.test` … `hospitalbank10@qatra.test` | `HospitalBank@123` |
| بنك دم مركزي | `bloodbank01@qatra.test` … `bloodbank10@qatra.test` | `BloodBank@123` |

تحتوي المستشفيات العشرة التي لديها بنك دم وبنوك الدم المركزية العشرة على مخزون موزع بين الفصائل الثماني، بإجمالي 3520 وحدة تجريبية. لا يُنشأ مخزون للمستشفيات التي يقتصر دورها على طلب الدم.

## ملاحظة

يبدأ النظام بحساب مشرف الصحة و40 حسابًا تجريبيًا مع مخزون لبنوك الدم، ودون طلبات دم أو نداءات تبرع مسبقة. تُحفظ البيانات محليًا في المتصفح، ولا يوجد Backend في هذه النسخة.
